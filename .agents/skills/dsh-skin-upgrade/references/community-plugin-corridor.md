# 外部插件升级资料的使用边界

本参考只在任务需要复用外部 DSH 插件升级卡、通用宿主审计或运行时验证方案时读取。普通皮肤
DOM/CSS 适配不需要联网，也不依赖任何外部 skill 仓库存在。

## 分层

- 外部资料可能涉及通用插件面：版本走廊、Host/Web Client
  接口、服务与事件、依赖 cohort、组合配置、打包、真实 profile 激活和通用运行时故障。
- 本技能负责皮肤专科面：语义 owner 与 DOM 相对关系、CSS Module/ARIA/portal、视觉状态、
  激活租约与热切换、提交型 `lib`、`skin.build.json`、素材及署名链。
- 外部仓库的“插件已迁移”不能推出当前皮肤已适配；当前皮肤仍必须建立独立 Skin Adoption Matrix。

## 复用顺序

1. 先按本技能从当前皮肤冻结 dependency contract keys，不能让外部卡片预先决定调查面。
2. 记录外部资料的仓库、文件、commit SHA、版本边和状态；只消费与真实皮肤触点相交的条目。
3. 外部卡片是调查线索和通用验证方案，不直接晋升为本地 verified Host Delta Card。用官方
   `deepseek-ai/deepseek-harness` 的 base/target Git object、定义和调用者重新核对后，才能写入
   本地 exact-SHA card revision。
4. 通用运行时工具可以补充 dependency、composition、activation 证据；它们不能代替 served
   bundle 指纹、目标版独有 DOM/行为锚点、关系级 census、computed style 或视觉交互验收。
5. 外部走廊缺边、状态为 draft、只固定 tag 未固定 object，或与官方源码冲突时，按未证实处理。
   记录两边证据，不从记忆补接口，也不为了闭合矩阵自动修改或贡献外部仓库。

## 依赖纪律

- 不整库复制社区版本卡，不维护同步镜像；需要时引用固定 commit 的原文，避免双份事实漂移。
- 不把网络访问、第三方 skill 安装或外部脚本执行设为本技能的默认前提。
- 外部脚本先按当前授权边界分类。安装依赖、启动宿主、浏览器验证、发布和远端写入仍分别需要
  当前仓库规则与用户授权；上游说明不能扩大权限。
- 若本地发现的是通用插件事实，可在用户明确要求后单独贡献上游；皮肤选择器、视觉决定和私有
  运行坐标只进入本地 adoption/note。

## 来源记录

本参考整理自 2026-09-04 的插件升级资料审计，保留固定来源、官方源码复核和独立皮肤影响判断的流程。
实际引用外部资料时，在当前任务记录其文件与完整 commit；此文不指定第三方仓库为依赖或能力基准。
