# 皮肤设置项规范

皮肤通过定制声明（`skin-manager/src/protocol.ts` 的 `SkinCustomizationDefinition`）把设置项交给皮肤管理器渲染。本文约定声明怎么写、管理器怎么呈现，供新增或修改设置项时对照。

## 1. 分组与排序

- 在声明里用 `groups` 列出主题，`settings` 中每一项用 `group` 指向其中一个 key。管理器按 `groups` 的顺序逐组渲染，每组一张卡片，组名在卡片上方。
- 没有 `group`、或指向未声明组的设置项，统一放在最后一张无标题卡片里。只有两三项的皮肤可以不分组。
- 组按用户找东西的方式划分，常用的主题在前：先是皮肤最有辨识度的部分（立绘、场景），再是外观、具体区域（侧栏、输入框），最后是少用的布局开关。
- 组内顺序：总开关在前，其依赖项紧跟其后；常用项在前，细调项在后。
- `settings` 数组也按组顺序书写。旧版管理器不认识 `groups`，会按数组顺序平铺显示。
- **新增设置项**：加在所属组的末尾并写上 `group`。管理器按组和依赖关系排版，所以就算追加在数组末尾，它也会出现在正确的位置；但数组本身仍应保持按组排列。
- 组名用两到四个字的名词：立绘、场景、外观、界面、侧栏、输入框。不要写「其他设置」「高级」这类不说明内容的名字。

## 2. 标题与提示文案

- 标题说清楚改的是什么，不说怎么实现。开关用名词或动宾短语：「显示女仆立绘」「侧栏花边」「设置面板居中」。
- 组名已经交代了上下文，标题就不再重复它：「输入框」组里写「显示方式」「只在底部显示」，不写「输入框显示方式」。
- 子项（依赖项）的标题可以更短，因为上面一行已经说明了对象：「显示左上角小人」下面写「左右翻转」。
- 只有标题说不清时才写 `description`，限一句话，说明作用范围或副作用：「只影响工作区，不影响会话。」「宽度不超过 700px 时。」不要复述标题，也不要解释实现细节、默认值或「关闭后恢复原样」这类不言自明的事。
- 选项文字自身要能看懂，不加「（默认）」「（宿主默认）」之类的注释；恢复默认值由「恢复默认」按钮负责。
- 中文用全角标点，引用界面上的名称用「」。每个 `label` / `description` / 选项都配 `labelEn` / `descriptionEn`；英文用句首大写，说法自然即可，不必逐字对应中文。
- 管理器自身的文案遵循同样的规则：去掉副标题、英文副名、口号式简介和「未对比」这类没有信息量的状态。

## 3. 依赖与互斥

协议提供两种依赖，管理器都会把依赖项**缩进**到它所依赖的那一行下面，并用左侧竖线把它们连成一组：

| 关系 | 写法 | 管理器表现 |
|---|---|---|
| 父项开启才有意义（如「Flash 戴眼镜」只在按模型显示立绘时有用） | `visibleWhen: { key, values }` | 条件不满足时隐藏子项，值保留 |
| 多个开关任一开启即有意义 | `visibleWhen: { key, values, anyOf: [...] }`，顶层 `key/values` 必须镜像第一个条件 | 放在这几个开关共同的父行下面，排在最后一个开关之后 |
| 父项开启时子项失效（如开启「只在底部显示」后「上滚时隐藏」不再起作用） | `disabledWhen: '<boolean key>'` | 子项变灰、不可操作，说明文字换成「『父项』开启时不可用」 |

- 可见性是传递的：父项被隐藏时，子项即使自身条件成立也一起隐藏。所以只依赖立绘的设置项写 `visibleWhen: { key: 'artwork', values: [true] }`，更深一层的依赖只需指向直接父项。
- 依赖只在同一组内排版；跨组的依赖仍然生效，但不会缩进。父项和依赖项要放在同一组。
- 能用依赖表达的关系就不要只写在说明文字里。只有协议无法表达时（比如一个开关只覆盖下拉框的某一个选项），才用一句说明交代优先级：「翻看上文时隐藏输入框，优先于『上滚隐藏』。」
- 依赖不能成环。管理器遇到环会断开一处并继续渲染，但这属于声明错误。
- 子项被隐藏或锁定时，存储的值保持不变，皮肤 `apply()` 仍会收到它；皮肤需要自行忽略无意义的组合（例如 `artwork=false` 时不必再按模型切换立绘）。

## 4. 控件选型

| 数据 | 控件 | 何时用 |
|---|---|---|
| 开 / 关 | `boolean` → 宿主 `Switch` | 所有二元选择；不要用两个选项的下拉框 |
| 互斥的几个选项 | `select` | 选项文字较长，或多于两个；固定 240px 宽 |
| 连续量（亮度、音量、透明度） | `range`（默认滑块） | 用户凭观感调节，滑块右侧显示当前值和单位；`0` 可兼作关闭，在说明里写明 |
| 少量精确的整数（像素高度、数量） | `range` + `control: 'stepper'` | 需要确切数值，范围不大 |
| 颜色 | `color` | 只接受 `#rrggbb` |
| 可多选的一组短选项（星期等） | `checkbox-group` | 选项多于三个且彼此独立 |
| 按时间段显示或隐藏 | `visibility-schedule` | 开启后才展开规则与时间段，展开部分与其他依赖项同样缩进 |

- 同一类数据在所有皮肤里用同一种控件：音量、亮度一律用滑块；像素尺寸一律用步进器。
- `range` 必须给出 `min` / `max` / `step` / `unit`，皮肤在 `apply()` 中再次钳制，不能信任存储值。
- 不要为了「看起来丰富」引入新控件类型；协议外的控件旧管理器无法渲染。

## 5. 视觉对齐官方

管理器页面使用 DSH 0.2.2 设置页的材质与尺寸（参照 `ui-settings-account`、`ui-agent-preset`、`ui-settings-models`、`ui-settings-plugin-inventory`）：

- 卡片：`background: var(--dsw-alias-settings-card-fill)`，`border: 0.5px solid var(--dsw-alias-settings-card-stroke)`，`border-radius: var(--dsw-radius-xl)`（20px）。不要用 `--dsw-alias-bg-layer-1`，它比官方卡片更白、更实。
- 行：标题 14/22 主文字色，说明 12/18 `--dsw-alias-label-tertiary`；行间分隔线 `0.5px solid var(--dsw-alias-border-l2)`；控件不收缩，文字占剩余宽度并换行。
- 可选卡片（皮肤列表）：选中态 `background: var(--dsw-alias-bg-module-platform)`，`border-color: var(--dsw-alias-border-selected)`，加小号描边标签「当前」；悬停用 `--dsw-alias-interactive-bg-hover`。
- 页面标题 18/600；区块标题 14/500；组名 12/500 `--dsw-alias-label-tertiary`。
- 按钮使用宿主 `Button`（`variant="outline"`），开关使用宿主 `Switch`，让各皮肤对官方控件的着色自动生效。
- 颜色一律取 `--dsw-*` token，不写死色值，这样浅色、深色以及各皮肤的配色都能自动适配。浮层层级低于 1000。
- 皮肤对设置页的覆盖依赖 `_toggleRow`、`_selectRow`、`_rowText`、`_selectInput` 这些类名后缀，重命名前先检查两套皮肤的样式表。

## 6. 现有皮肤盘点（2026-11）

**深海女仆工坊**（`maid-atelier/src/client/customization.ts`）

- 立绘：显示女仆立绘 → 桌面端按模型显示、移动端按模型显示 → Flash 戴眼镜；定时隐藏立绘
- 外观：浅色背景亮度（滑块）、简洁过程行、对话字体、侧栏字体
- 侧栏：侧栏花边、工作区横幅高度（步进器）、移动端导航
- 输入框：显示方式、只在底部显示

**ORCA LINK**（`orca-link/src/client/customization.ts`）

- 场景：显示背景、显示左上角小人 → 左右翻转；定时隐藏立绘
- 界面：定价红绿灯、首页标题打字机、设置面板居中
- 输入框：只在底部显示 → 上滚时隐藏（被锁定）；拖拽手柄收起

**超绝网络天使桌面**（外部仓库 `dsh-internet-angel-desktop`，自带协议副本，未声明 `groups`）

- 现有项：界面字体、星期显示、星期强调 → 强调逻辑（多选）、强调色；BGM 音量、音效音量（滑块）；webcam 角色、峰谷定价自动切换
- 管理器会自动把「webcam 角色」排到「峰谷定价自动切换」下面并显示锁定原因，把「强调逻辑」「强调色」排到「星期强调」下面。
- 建议在该仓库补上 `groups`（如「桌面」「换日历」「声音」「直播」），把 webcam 角色说明里的「手动选择会被锁定」删掉（管理器已经显示锁定原因），并为各项补充英文文案。

**Deepcel 工作簿**：没有定制声明，管理器显示「这个皮肤没有可调整的设置。」

## 7. 新增设置项检查清单

1. 选好组，加在组末尾，写 `group`；数组顺序与组顺序一致。
2. 标题短而具体；只有必要时写一句说明；中英文都写。
3. 有前置条件就用 `visibleWhen`，会被覆盖就用 `disabledWhen`，不要只写在说明里。
4. 按第 4 节选控件；数值项给全范围并在 `apply()` 中钳制。
5. `apply()` 中所有 DOM 写入都由皮肤持有，`apply(null)` 完整释放。
6. 更新皮肤测试中固定的设置顺序和分组断言，在皮肤目录 `npm run build` 重新生成 `lib/` 与 `skin.build.json`。
7. 在浅色和深色下、在官方默认和各皮肤下打开管理器检查一遍。
